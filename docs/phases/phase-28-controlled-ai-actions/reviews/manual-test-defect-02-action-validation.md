## 1. Executive Summary & Root Cause

During live manual browser testing of Phase 28 Controlled AI Actions, asking Project Copilot an action-oriented question (*"Change the priority of 'Design JWT Token Scheme and Payload Structure' to urgent."*) resulted in an HTTP 500 `AIValidationError`.

### Root Cause Analysis
1. **Model Casing & Whitespace Variations**: Gemini generated an action proposal with capitalized enum values (e.g. `priority: "Urgent"` or `"URGENT"`, `status: "Done"`) or formatted date strings as date-only (e.g. `"2026-07-30"`). Strictly strict Zod `z.enum(["low", "medium", "high", "urgent"])` rejected `"Urgent"` with `"Priority must be one of: low, medium, high, urgent"`.
2. **Empty `explanation` String**: Gemini generated `explanation: ""` (empty string) because `minLength: 1` was stripped from Gemini's wire schema protobuf during schema adaptation. Strict Zod `.min(1)` rejected `""` with `"Explanation cannot be empty"`.
3. **Error Logging Truncation**: `validateAIResponse` passed `result.error.format()` to `AIValidationError`, which Node.js default `util.inspect` truncated at depth 2 as `arguments: [Object]`, `explanation: [Object]`.

## 3. Why Informational Requests Succeeded While Action Requests Failed

Informational queries (e.g., *"What are the biggest risks?"*) return `proposedAction: null`. Because `null` contains no `arguments` or `explanation` properties, it passed canonical Zod validation cleanly.

Action-oriented queries return a non-null `proposedAction` object, triggering Zod validation on `arguments` and `explanation`.

---

## 4. Why Existing Automated Tests Missed This

Automated unit tests used mock fixtures with pre-formatted lowercase strings (e.g. `priority: "urgent"`, `explanation: "Valid reasoning"`). Offline tests did not simulate Gemini's tendency to output capitalized strings (`"Urgent"`) or empty explanation strings (`""`).

---

## 5. Corrective Architectural Fix Implemented

The fix maintains strict canonical Zod validation boundaries without weakening domain constraints or enum whitelists:

1. **Enum Case-Insensitivity & Preprocessing**:
   Updated all 5 action Zod schemas (`CreateTaskPayloadSchema`, `UpdateTaskStatusPayloadSchema`, `UpdateTaskPriorityPayloadSchema`, `UpdateTaskDueDatePayloadSchema`, `AddTaskLabelPayloadSchema`) using `z.preprocess()` to trim and lowercase string enum inputs. `"Urgent"` and `"URGENT"` map to `"urgent"`. Invalid enum values (e.g. `"EXTREME"`) remain 100% rejected.

2. **Explanation Preprocessing & Fallback**:
   `explanation` in all 5 action schemas preprocesses empty or whitespace-only strings to a fallback string `"Proposed action per user request."` while preserving non-empty explanations. Omitted/missing (`undefined`) `explanation` fields continue to fail required validation.

3. **Date String Preprocessing**:
   Date-only strings (`"2026-07-30"`) are preprocessed to ISO datetime strings (`"2026-07-30T00:00:00.000Z"`), satisfying Zod `.datetime()` constraints.

4. **Enhanced Error Logging**:
   Updated `validateAIResponse()` in `server/src/ai/validation/ai-response.validator.ts` to include `result.error.issues` directly in `AIValidationError`, providing un-truncated field paths and exact error messages.
