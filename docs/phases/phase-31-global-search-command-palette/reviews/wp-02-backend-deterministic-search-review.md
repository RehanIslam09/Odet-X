# Phase 31 — WP-02 Work Package Completion Review
## Backend Deterministic Search Engine

### 1. Executive Summary

Work Package **WP-02 — Backend Deterministic Search Engine** has been successfully implemented and verified against the frozen Phase 31 Architecture Contract (`docs/phases/phase-31-global-search-command-palette/01-architecture-contract.md`).

WP-02 provides the deterministic, owner-isolated MongoDB search engine (`searchGlobalEntities`) covering:
- **Entities**: Projects, Tasks, Milestones, and ProjectMemories.
- **Tenant & Visibility Scoping**: Strict owner equality on every query (`owner == ownerId`) and mandatory parent-project active/visible checks (`project.owner == ownerId`, `isDeleted == false`, `archived == false`) for child entities.
- **N+1 Prevention**: Batch parent project resolution retrieving names and active states in a single query.
- **Deterministic Ranking**: Integrates WP-01 primitives (`calculateRelevanceScore`, `compareSearchResults`, `generateMemorySnippet`, `generateNavigationUrl`).
- **Memory Privacy**: Plain-text bounded snippets (<= 100 characters), zero raw memory leakage, zero HTML injection.
- **Zero Side-Effects**: Read-only database operations (`0` writes to entities, Activity logs, or recommendations, `0` AI calls).

### 5. Tenant Isolation & Parent Project Visibility Architecture

1. **Owner Equality**: Every Mongoose query includes `{ owner: ownerObjectId }`.
2. **Parent Project Resolution**:
   - For all candidate child entities (`Task`, `Milestone`, `ProjectMemory`), their `projectId` is collected.
   - A single batch query checks:
     ```ts
     Project.find({
       _id: { $in: parentObjectIds },
       owner: ownerObjectId,
       isDeleted: false,
       archived: false,
     })
     ```
   - Child items whose parent project is missing, deleted, archived, or unowned are strictly dropped.

---

### 6. Query Normalization & Regex Safety

- User inputs are normalized using WP-01 `normalizeSearchQuery()`.
- Regex special characters (`.*+?^${}()|[\]\\`) are sanitized using `escapeRegex()`.
- Inputs with `< 2` characters return immediately (`totalResults: 0, items: []`) without calling MongoDB.

### 7. Candidate Retrieval Bounds & Performance

- **`SEARCH_CANDIDATE_LIMIT_PER_ENTITY = 50`**: Bounds MongoDB query candidate fetching per entity collection.
- **`SEARCH_PER_TYPE_LIMIT = 5`**: Caps per-entity results when `type=all`.
- **`SEARCH_ALL_MAX_RESULTS = 20`**: Caps total global search results when `type=all`.
- **`SEARCH_MAX_LIMIT = 50`**: Caps requested limits for type-specific searches.

---

### 8. Deterministic Ranking & Tie-Breaking

- Candidate items are scored using `calculateRelevanceScore()`:
  - Exact Title: 100
  - Prefix Title: 80
  - Substring Title: 60
  - Task Label: 40
  - Description / Memory Content: 30
- Tie-Breaking Comparator (`compareSearchResults`):
  1. `score DESC`
  2. `updatedAt DESC`
  3. `id ASC` (lexicographical string comparison)

---

### 9. ProjectMemory Privacy Protections

- Raw `content` field is stripped from `SearchResultDto`.
- Subtitle contains safe snippet generated by `generateMemorySnippet(content, query)` (max 100 characters total).
- HTML tags (e.g. `<script>`, `<mark>`) are treated as plain text with no HTML rendering.
